CompTIA Objectives 1.2, 1.6, 2.3

Network Fundamentals

A computer network is a collection of interconnected endpoints, appliances, and transmission media that exchange data through standardised protocols. Networking is described through layered reference models: each layer solves one problem, exposes a service to the layer above it, and stays independent of the layers below — which is what allows a Cisco switch, a Fortinet firewall, and a Linux server from three different vendors to interoperate on the same segment.

TCP/IP Model and Encapsulation

The TCP/IP model condenses the stack into four layers: Link (OSI 1–2), Internet (OSI 3), Transport (OSI 4), and Application (OSI 5–7). TCP/IP is the model actually implemented by the internet; OSI remains the vocabulary used for troubleshooting and exam questions.

Encapsulation is the process by which each layer prepends its own header as data descends the stack — application data gains a TCP header, then an IP header, then an Ethernet header and trailer. The receiving host reverses the process (de-encapsulation).

Why layering matters in practice

Faults can be isolated layer by layer. No link light is Layer 1; a wrong VLAN is Layer 2; an unreachable default gateway is Layer 3; a blocked TCP port is Layer 4. Working bottom-up turns troubleshooting from guesswork into a repeatable procedure.

Network Components

CompTIA Objective 1.2 — Networking Appliances

Appliances may be deployed as dedicated physical hardware or as virtual instances on a hypervisor. The function is identical, but virtual appliances scale elastically and are provisioned by code rather than by a rack visit.

Switch — Layer 2

Forwards frames using a MAC address table populated by source-address learning. Floods unknown unicast, broadcast, and multicast. Each port is its own collision domain; each VLAN is its own broadcast domain.

Router — Layer 3

Forwards packets between distinct IP networks using longest-prefix match. Runs static routes or dynamic protocols (OSPF, EIGRP, BGP), terminates broadcast domains, and typically performs NAT at the edge.

Access Point — Layer 1–2

Bridges 802.11 wireless clients onto the wired LAN. Advertises an SSID, negotiates authentication (WPA2/WPA3-PSK or 802.1X Enterprise), and is centrally managed by a wireless LAN controller in campus deployments.

Firewall — Layer 3–4, NGFW to 7

Enforces policy between security zones. Stateful inspection tracks each flow in a state table so return traffic is permitted implicitly. NGFWs add application awareness, user identity, and TLS inspection.

Also assessed under Objective 1.2

  • • IDS / IPS: an IDS monitors a copy of traffic out-of-band and alerts; an IPS sits inline and can drop malicious traffic. Both detect via signatures or behavioural anomaly baselines.
  • • Load balancer: distributes sessions across a server pool using round-robin, least-connections, or weighted algorithms. Provides health checks, session persistence, and TLS offload.
  • • Proxy: terminates and re-originates sessions on behalf of clients. A forward proxy applies egress filtering and caching; a reverse proxy fronts servers for security and offload.

Network Resources

CompTIA Objective 1.2 — Servers, Storage, and Endpoints

Resources are the services and storage that endpoints consume across the network, centralising data so it can be backed up, secured, and audited in one place rather than scattered across individual workstations.

Server roles

  • Web server — serves HTTP on TCP/80 and HTTPS on TCP/443, terminating TLS and returning static or dynamically generated content.
  • File server — shares directories over SMB/CIFS (TCP/445) for Windows estates or NFS (TCP/2049) for UNIX and Linux, applying share and NTFS/POSIX permissions.
  • Database server — hosts relational engines such as PostgreSQL (TCP/5432), MySQL (TCP/3306), or MS SQL Server (TCP/1433), guaranteeing ACID transactional integrity.
  • Endpoints — workstations, laptops, thin clients, VoIP handsets, printers, and IoT devices. They consume the services above and represent the largest attack surface on the network.

NAS vs. SAN — the distinction that gets tested

NAS — file-level storage

  • • Self-contained appliance on the existing Ethernet LAN
  • • Presents shared folders via SMB or NFS
  • • The NAS owns its own filesystem — clients request files, not disk blocks
  • • Simple to deploy; ideal for departmental shares and backup targets

SAN — block-level storage

  • • Dedicated high-speed storage fabric
  • • Presents raw LUNs over Fibre Channel or iSCSI (TCP/3260)
  • • The host formats the LUN, so it appears as a locally attached disk
  • • Used for virtualisation clusters and latency-sensitive databases

Network Geography

CompTIA Objective 1.6 — Network Types by Scope

The scope of a network dictates who owns the transmission medium, what bandwidth is economically available, and how much latency the design must tolerate. Ownership is the key distinction: LAN media are privately owned, whereas WAN circuits are leased from a service provider.

SD-WAN

Software-defined WAN abstracts the control plane from the underlying transport. Its defining traits:

  • • Transport agnostic — MPLS, broadband, and LTE/5G used interchangeably
  • • Application-aware dynamic path selection
  • • Central policy management
  • • Zero-touch provisioning of branch devices

SDN

Software-defined networking separates the control plane from the data plane and drives forwarding decisions from a central controller through an API. SD-WAN is that same architectural principle applied specifically to wide-area links.

Wired Network Topology

CompTIA Objective 1.6 — Physical and Logical Topologies

Distinguish the physical topology (how cable is actually run) from the logical topology (how frames actually flow). Modern Ethernet is almost universally a physical star that behaves logically as a point-to-point switched fabric.

Star / hub-and-spoke

Every node homes back to a central switch. Dominant in modern LANs: a single cable fault isolates one host and troubleshooting is straightforward, but the central switch is a single point of failure unless it is stacked or redundant.

Mesh

Nodes interconnect with multiple redundant paths. A full mesh of n nodes requires n(n−1)/2 links, so cost and configuration complexity grow quadratically. Partial mesh is the practical compromise for WAN cores.

Ring

Nodes form a closed loop with data circulating in one direction. Legacy Token Ring and FDDI; still seen in provider metro rings, where a dual counter-rotating ring wraps around a break to survive a single cut.

Bus

All nodes share one common backbone terminated at both ends. Legacy 10BASE2/10BASE5. Minimal cabling, but the shared medium is a single collision domain and one break can bring down the segment.

Point-to-point

A dedicated link between exactly two endpoints — a switch uplink, a leased circuit, or a wireless bridge between buildings. No contention, deterministic performance.

Hybrid

Any combination of the above — which is what real networks are: a star-of-stars access layer riding on a partially meshed core.

Wireless Network Topology

CompTIA Objective 2.3 — Wireless Network Types

Wireless shares an unlicensed half-duplex medium, so all stations in range contend for airtime using CSMA/CA. Design therefore revolves around non-overlapping channel plans (1, 6, 11 in 2.4 GHz), appropriate band selection, and controlled cell overlap for roaming.

Infrastructure mode

Clients associate to an AP, which bridges them to the wired distribution system. One AP and its clients form a BSS identified by a BSSID; multiple APs sharing an SSID form an ESS, enabling roaming. The default enterprise design.

Ad hoc (IBSS)

Peer-to-peer association with no AP and no distribution system. Fast to stand up for a temporary file transfer, but it does not scale, offers weak security, and provides no roaming.

Wireless mesh

APs relay traffic for one another over a wireless backhaul, so only a subset need a wired uplink. Self-forming and self-healing; ideal for warehouses, outdoor sites, and heritage buildings where cabling is impractical.

Point-to-point

Two directional (Yagi or parabolic) antennas aimed at each other to bridge buildings over distance. Requires line of sight and correct Fresnel zone clearance.

Frequency bands and modern standards

  • • 2.4 GHz — travels furthest and penetrates walls, but offers only three non-overlapping 20 MHz channels and suffers heavy interference.
  • • 5 GHz — far more channels at shorter range; the workhorse band for enterprise deployments.
  • • 6 GHz (Wi-Fi 6E) — clean spectrum with the widest channels and the shortest range.
  • • 802.11ax (Wi-Fi 6/6E) — introduces OFDMA for uplink and downlink multi-user scheduling, MU-MIMO spatial streams, and target wake time, raising efficiency in high-density environments rather than just raw peak rate.

Datacenter Topology

CompTIA Objective 1.6 — Data Centre Architectures

Traffic patterns drive the design. Classic client-server generates north-south traffic between users and servers; virtualisation, clustering, and microservices generate far more east-west traffic between servers inside the data centre — which is precisely what the older hierarchy handles poorly.

Three-tier hierarchical model

  • • Layers: Core → Distribution → Access
  • • Access ports connect servers; distribution aggregates and applies policy and inter-VLAN routing; core provides high-speed backbone transit
  • • Predictable, well-understood, clear fault domains
  • • Collapsed core merges core and distribution into one tier for smaller sites

Spine and leaf

  • • A two-tier Clos fabric
  • • Every leaf connects to every spine; spines never connect to one another
  • • Servers attach only to leaves
  • • Any server-to-server path is a consistent two hops — leaf → spine → leaf

Why spine-leaf wins

Uniform latency regardless of which racks communicate, full bisectional bandwidth via ECMP across all spines, and horizontal scale — add a leaf for more ports, add a spine for more bandwidth, without redesigning the fabric. This is the hyperscale cloud standard.

Three-tier limitations

Spanning Tree blocks redundant links to prevent loops, leaving capacity idle. East-west traffic between access switches must traverse the distribution or core layer, so latency varies by path and the aggregation layer becomes a bottleneck.

Traffic flows

North-south traffic moves between the data centre and the outside world, crossing tiers. East-west traffic moves server to server within the fabric and now dominates virtualised workloads.

Performance Metrics

Metric Definition and practical impact
BandwidthTheoretical maximum data rate of a link (Mbps/Gbps) — the width of the pipe, not the water flowing through it.
ThroughputData rate actually achieved under real traffic. Always lower than bandwidth once protocol overhead, contention, and retransmission are accounted for.
LatencyOne-way delay in milliseconds. Interactive voice and video degrade noticeably beyond roughly 150 ms end-to-end.
JitterVariation in latency between successive packets. Real-time media tolerates steady delay far better than inconsistent delay; jitter buffers absorb only a limited amount.

Module 2

OSI Model

The seven-layer reference model, the protocol data unit produced at each layer, and the encapsulation and decapsulation process that moves data down one stack and up another.

CompTIA Objective 1.1

The Seven Layers

Published by the ISO in 1984 as standard 7498-1, the Open Systems Interconnection model decomposes network communication into seven abstraction layers. No production stack implements OSI literally — the internet runs on TCP/IP — but OSI remains the lingua franca of network engineering: it is how faults are localised, how vendors scope their products, and how CompTIA phrases Objective 1.1.

Each layer consumes the service of the layer beneath it and presents a service to the layer above, so a change in cabling never forces a change in HTTP. That independence is the entire point of the model.

Layer by Layer

L1

Physical

PDU: Bit
Function
Transmits an unstructured bit stream over the medium. Defines voltage levels, line coding, timing, modulation, pin assignments, and the mechanical shape of connectors. It has no concept of addressing and no idea what the bits mean.
Standards & media
1000BASE-T and 10GBASE-T over Cat 5e/6/6a copper, 1000BASE-LX over single-mode fibre, 802.11 radio, RS-232, DSL, DOCSIS. Connectors include RJ45, LC, SC, and MPO.
Devices
Cabling, patch panels, transceivers (SFP/QSFP), media converters, repeaters, and legacy hubs. A hub is a pure Layer 1 device: it repeats every incoming bit out of every other port.
Typical faults
No link light, excessive attenuation on an over-long run, bent or dirty fibre, EMI from adjacent power cable, duplex or speed mismatch, TX/RX pairs crossed.
L2

Data Link

PDU: Frame
Function
Packages bits into frames for delivery across a single link, provides physical addressing, and detects corrupted frames. Split into the LLC sublayer, which interfaces upward to Layer 3, and the MAC sublayer, which governs access to the shared medium.
Addressing
48-bit MAC addresses written as twelve hexadecimal digits. The first 24 bits are the OUI identifying the vendor; the remaining 24 bits identify the interface. Scope is strictly local — a MAC address never crosses a router.
Protocols
Ethernet (802.3), Wi-Fi (802.11), ARP for resolving IP to MAC, STP/RSTP (802.1D/802.1w) for loop prevention, 802.1Q VLAN tagging, LACP (802.3ad) for link aggregation.
Error detection
A 4-byte Frame Check Sequence trailer carries a CRC-32. A frame failing the check is silently discarded — Layer 2 detects errors but does not correct them; recovery is left to Layer 4 or the application.
Devices
Switches and bridges, plus wireless access points bridging 802.11 to 802.3.
L3

Network

PDU: Packet
Function
Provides logical addressing and end-to-end path determination across multiple links. This is the first layer whose addressing is globally meaningful, which is what makes internetworking possible.
Addressing
32-bit IPv4 addresses in dotted decimal with a subnet mask, or 128-bit IPv6 addresses in hexadecimal. The mask splits every address into a network portion and a host portion, which is how a router decides whether a destination is local or remote.
Forwarding logic
The router consults its routing table and selects the longest prefix match. It decrements the TTL (IPv4) or Hop Limit (IPv6) on every hop and discards the packet at zero — precisely the mechanism traceroute exploits.
Protocols
IPv4 and IPv6 for addressing; ICMP and ICMPv6 for diagnostics; OSPF, EIGRP, and BGP for dynamic routing; IPsec for encrypted tunnels.
Devices
Routers and Layer 3 switches, which perform hardware-accelerated inter-VLAN routing.
L4

Transport

PDU: Segment / Datagram
Function
Delivers data end to end between processes rather than between hosts, using port numbers to multiplex many conversations across one IP address. Also handles segmentation, flow control, and — for TCP — reliability.
TCP — connection-oriented
Establishes a session with the three-way handshake (SYN, SYN-ACK, ACK) and closes it with FIN/ACK exchanges. Guarantees ordered delivery through sequence numbers, retransmits unacknowledged data, and throttles the sender via a sliding window and congestion control. Header is 20 bytes minimum.
UDP — connectionless
An 8-byte header, no handshake, no acknowledgement, no ordering, no retransmission. The low overhead and absence of head-of-line blocking make it correct for DNS, DHCP, VoIP media, and streaming, where a late packet is worse than a lost one.
Port ranges
Well-known 0–1023, registered 1024–49151, dynamic/ephemeral 49152–65535. The pairing of source IP, source port, destination IP, and destination port forms the socket that uniquely identifies a flow.
Devices
Stateful firewalls and load balancers, which make decisions on port numbers and connection state.
L5

Session

PDU: Data
Function
Establishes, manages, synchronises, and gracefully terminates the dialogue between two applications. Where Layer 4 maintains a connection, Layer 5 maintains a conversation that may span several connections.
Services
Dialogue control (simplex, half-duplex, full-duplex), session checkpointing so a long transfer resumes from the last marker rather than restarting, and orderly teardown ensuring both parties agree the exchange is finished.
Protocols
NetBIOS session service, RPC, SMB session setup, PPTP and L2TP tunnel control, SIP for establishing VoIP calls, H.245.
In practice
In the TCP/IP model this layer has no independent existence — its responsibilities are absorbed into the application. It is retained in OSI because the distinction between a transport connection and an application dialogue is genuinely useful when reasoning about failures.
L6

Presentation

PDU: Data
Function
Translates between the application's data representation and a common wire format, so two hosts with different internal encodings still understand one another. Often called the syntax layer.
Translation
Character-set conversion between ASCII, EBCDIC, and Unicode; byte-order normalisation; serialisation formats such as XML, JSON, and ASN.1.
Compression
Reduces payload size before transmission — GZIP and Brotli for text, codec-level compression for JPEG, GIF, PNG, MPEG, and H.264 media.
Encryption
TLS and its predecessor SSL are conventionally mapped here, since cipher negotiation and payload encryption are a transformation of representation rather than of transport. In implementation terms TLS straddles Layers 5 and 6.
L7

Application

PDU: Data
Function
The layer user-facing software actually talks to. It does not mean the application itself — a browser is not Layer 7; the HTTP the browser speaks is. It defines the request and response semantics the two endpoints share.
Web & mail
HTTP (TCP/80) and HTTPS (TCP/443); SMTP (TCP/25, submission on 587) for sending mail; POP3 (TCP/110) and IMAP (TCP/143) for retrieving it.
Infrastructure services
DNS (UDP/53, TCP/53 for zone transfers and large responses), DHCP (UDP/67 and 68), NTP (UDP/123), SNMP (UDP/161, traps on 162), LDAP (TCP/389, LDAPS 636).
File transfer & remote access
FTP (TCP/20 data, 21 control), SFTP and SSH (TCP/22), Telnet (TCP/23, unencrypted and deprecated), RDP (TCP/3389), SMB (TCP/445).
Devices
Next-generation firewalls, web application firewalls, reverse proxies, and application-aware load balancers all inspect at this layer.

Encapsulation & Decapsulation

Data does not travel sideways between peer layers — it travels down the sender's stack and up the receiver's. On the way down, each layer prepends its own header (and, at Layer 2, appends a trailer) to whatever it received from above, treating that entire unit as an opaque payload. This is why a single HTTP GET leaves the sender wrapped in a TCP header, an IP header, and an Ethernet header and trailer.

On the way up the receiver reverses the process exactly, each layer stripping and acting on its own header before handing the remainder upward.

What each header actually adds

Layer Overhead Contents
Transport (TCP) 20 bytes Source and destination ports, sequence and acknowledgement numbers, window size, flags. UDP adds only 8 bytes: ports, length, checksum.
Network (IPv4) 20 bytes Source and destination IP, TTL, protocol number identifying the Layer 4 payload, header checksum. IPv6 uses a fixed 40-byte header with no checksum.
Data Link (Ethernet) 18 bytes A 14-byte header carrying destination MAC, source MAC, and EtherType, plus a 4-byte FCS trailer. An 802.1Q VLAN tag adds a further 4 bytes.

Rewritten at every hop

The Layer 2 header is stripped and rebuilt by each router along the path, because MAC addressing is only locally significant. The Layer 3 header persists end to end, with only the TTL and checksum changing. This single fact explains most confusion about why a packet capture looks different at each hop.

MTU, fragmentation, and jumbo frames

  • MTU — the Maximum Transmission Unit is the largest Layer 3 payload a link will carry. Standard Ethernet is 1500 bytes, giving a 1518-byte frame once header and trailer are counted.
  • Fragmentation — an IPv4 packet exceeding the next link's MTU is split into fragments and reassembled by the destination host, at a cost in CPU and throughput. IPv6 forbids fragmentation in transit: the router drops the packet and returns ICMPv6 Packet Too Big.
  • Path MTU Discovery — the sender sets the Don't Fragment bit and lowers its segment size in response to ICMP errors. Firewalls that blanket-block ICMP break this, producing the classic fault where small packets succeed and large transfers hang.
  • Jumbo frames — MTUs up to roughly 9000 bytes, used on storage and virtualisation networks to cut per-packet overhead. Every device in the path must agree; a single mismatched hop causes silent drops.

Ports and Protocols

How a single IP address serves many processes at once — port fundamentals, the TCP and UDP trade-off, the default port assignments worth memorising, and how to find what is listening.

CompTIA Objective 1.4

Port Fundamentals

A port number is a 16-bit identifier that lets a single IP address host many simultaneous conversations. The IP address answers which machine; the port answers which process on that machine. Without ports, a server could offer exactly one service.

IANA divides the 65,536 available numbers into three ranges, and knowing which range a number falls into tells you immediately whether you are looking at a server or a client.

0 – 1023

Well-known

Assigned to standard services. Binding to one usually requires administrative privilege.

1024 – 49151

Registered

Reserved by vendors for specific applications — RDP on 3389 and SIP on 5060 live here.

49152 – 65535

Dynamic / ephemeral

Drawn at random by a client for the source port of an outbound connection.

The socket — a four-tuple

A connection is uniquely identified by four values: source IP, source port, destination IP, destination port. This is why one browser can hold six simultaneous connections to the same web server — each uses a different ephemeral source port.

Only the destination port is predictable, which is precisely what makes port scanning possible. Note also that running a service on a non-standard port is obscurity, not protection: a scanner that fingerprints service banners identifies SSH on 2222 as readily as on 22.

TCP versus UDP

TCP

Connection-oriented

  • • Three-way handshake (SYN, SYN-ACK, ACK) before any data moves
  • • Sequence and acknowledgement numbers guarantee ordered delivery
  • • Lost segments are retransmitted automatically
  • • Sliding window and congestion control throttle the sender
  • • Minimum header 20 bytes
UDP

Connectionless

  • • No handshake — the first packet carries payload
  • • No acknowledgement, ordering, or retransmission
  • • No congestion control; the application supplies any reliability
  • • Immune to head-of-line blocking
  • • Header is only 8 bytes

When TCP is correct

Anything where completeness matters more than timeliness: web pages, email, file transfer, database queries, remote shells. A missing byte in a downloaded archive corrupts the file, so waiting for a retransmission is the right trade.

When UDP is correct

Anything where a late packet is worthless: VoIP audio, live video, gaming, telemetry. Also correct for short request-response exchanges such as DNS and DHCP, where a handshake would cost more than simply re-asking.

Head-of-line blocking

Because TCP guarantees order, one lost segment stalls every byte queued behind it until the retransmission arrives. For a voice call this produces a freeze followed by a burst — far worse than dropping the lost audio and continuing, which is exactly what UDP does.

Services in Context

Web — HTTP 80 and HTTPS 443

HTTPS is not a different protocol but HTTP carried inside a TLS session. The handshake negotiates a cipher suite and validates the server certificate before any request is sent — which is why a certificate name mismatch breaks the connection before the page is ever requested.

Email — SMTP sends, POP3/IMAP retrieve

SMTP moves mail outward and between servers; it does not retrieve mail. A client that can send but not receive has a working SMTP path and a broken POP3 or IMAP one — the single most useful diagnostic split in mail troubleshooting.

POP3 versus IMAP

POP3 downloads and removes, leaving one authoritative copy on the client — poor for multiple devices. IMAP leaves the message on the server and synchronises flags, folders, and read state, so a message opened on a phone shows as read on a laptop.

FTP vs SFTP vs FTPS

FTP is plaintext on 20/21. SFTP is a subsystem of SSH on port 22 — a completely different protocol. FTPS is the original FTP wrapped in TLS. The naming similarity between SFTP and FTPS is a classic exam trap.

Remote access and infrastructure services

  • SSH (22) — encrypted shell, port forwarding, and file transfer. Prefer key-based authentication over passwords; the host key fingerprint is what protects against interception on first connection.
  • Telnet (23) — retained on the exam as the insecure counterexample. Its one remaining legitimate use is testing whether an arbitrary TCP port is open.
  • RDP (3389) — full graphical Windows sessions. Expose it through a VPN or gateway rather than directly, and require network level authentication.
  • DNS (53) — UDP for speed, falling back to TCP for large responses and zone transfers. A resolution failure looks exactly like a total outage to users, which is why it is the first thing to test after basic connectivity.
  • DHCP (67/68) — the DORA exchange: Discover, Offer, Request, Acknowledge. Discover is a broadcast, so a client on a different subnet needs a relay agent or IP helper address on the router.
  • NTP (123) — synchronises clocks against a stratum hierarchy. Certificate validation, Kerberos tickets, and correlated log timelines all depend on it, so a drifted clock produces failures that look unrelated to time.

ICMP and Finding Open Ports

ICMP has no ports

The Internet Control Message Protocol is a Layer 3 protocol carried directly inside IP as protocol number 1. It has no port numbers at all, because it signals conditions about the network rather than delivering data to a process. IPv6 uses ICMPv6, protocol number 58.

Media and Cabling Distribution

Every abstraction in the OSI model eventually resolves to a physical signal on a physical medium. Media choice is a negotiation between required bandwidth, distance, electrical environment, and budget — and the wrong choice surfaces later as intermittent faults that are far harder to diagnose than an outright failure.

MDF — Main Distribution Frame

The building's primary termination point, where the provider circuit enters and core switching lives. One per building.

IDF — Intermediate Distribution Frame

A floor or wing wiring closet fed from the MDF. Access switches live here and horizontal cabling radiates to work areas.

Backbone versus horizontal cabling

Backbone (vertical) cabling connects MDF to IDF and is almost always fibre — the runs are long and the aggregate bandwidth is high.

Horizontal cabling runs from the IDF to the wall outlet and is copper, capped at 90 m of solid-core permanent link plus 10 m of stranded patch cord — 100 m total. That 100 m figure is a channel budget, not a cable length.

  • Patch panel — horizontal runs terminate permanently on the rear; short patch cords connect the front to a switch port. Moves and changes touch only the patch cord, never the permanent link.
  • Demarcation point — the boundary where provider responsibility ends and yours begins. Establishing which side of the demarc a fault sits on is the first step in any circuit escalation.
  • Plenum versus non-plenum — plenum-rated jacket (FEP or low-smoke PVC) is mandatory in air-handling spaces such as raised floors and the void above a suspended ceiling, because standard PVC emits toxic smoke when it burns. A fire-code requirement, not a performance one.

Copper Media and Connections

Twisted pair remains the default for the run to the desk. The twisting itself is the engineering: two conductors carrying equal and opposite signals pick up interference almost identically, and the receiver's differential amplifier cancels anything common to both. Tighter twists, and more of them per metre, give higher category ratings.

UTP — Unshielded Twisted Pair

Four pairs in a plain jacket, relying purely on twist rate for noise rejection. Cheaper, thinner, and more flexible — the default for ordinary office cabling.

STP — Shielded Twisted Pair

Adds foil or braid around individual pairs, the whole bundle, or both. Required near motors, fluorescent ballasts, lift shafts, and industrial plant. Bond the shield to ground at one end only — grounded at both ends it becomes an aerial and makes interference worse.

Coax such as RG-6 with F-type connectors carries cable broadband and CCTV; RG-58 with BNC is legacy Ethernet. Twinaxial direct attach copper (DAC) terminates in an SFP+ or QSFP form factor and links adjacent racks over a few metres far more cheaply than optics.

The same standard at both ends gives a straight-through cable — what virtually everything uses today. Termination technique

Strip only the jacket, never the conductor insulation. Preserve the twist to within 13 mm of the termination — untwisting further is a leading cause of near-end crosstalk failures. Fibre Media and Connections

Fibre carries modulated light through a glass core rather than current through copper. That makes it immune to electromagnetic interference, incapable of radiating a signal that could be tapped passively, and free of any ground-loop concerns between buildings. It is the default for backbone, inter-building, and any run beyond the 100 m copper limit.

Single-mode (SMF)

  • • Core roughly 9 microns — one propagation path, no modal dispersion
  • • Narrow-linewidth laser at 1310 or 1550 nm
  • • Reaches tens of kilometres, highest bandwidth
  • • Jacket conventionally yellow

Multimode (MMF)

  • • Core 50 or 62.5 microns — many simultaneous paths
  • • Cheaper VCSEL transmitters at 850 nm
  • • Modal dispersion limits reach to a few hundred metres
  • • Orange for OM1/OM2, aqua for OM3/OM4, violet for OM5

Never mix single-mode and multimode

Connecting a 9-micron core to a 50-micron one produces enormous loss. The link may come up marginally and then fail intermittently under load — far harder to diagnose than a link that simply stays down. Attenuation is loss of optical power over distance in dB; dispersion is the spreading of a pulse until adjacent bits blur. Both set the practical distance limit.

Connector types

MPO / MTP

Polish types — UPC and APC

UPC — Ultra Physical Contact

Ferrule polished flat with a slight dome. Return loss around -50 dB. Conventionally blue. The general-purpose choice for enterprise data links.

APC — Angled Physical Contact

8-degree angled ferrule. Reflected light is deflected into the cladding rather than straight back down the core, giving return loss around -60 dB. Conventionally green. Required for RF video and long-haul DWDM.

Never mate APC to UPC

The angled and flat faces cannot make full contact. The result is a large air gap, severe insertion loss, and physical damage to both ferrules. The colour coding — green for APC, blue for UPC — exists to prevent exactly this.

Contamination: a single dust particle on a 9-micron core can obscure a meaningful fraction of it. Inspect and clean every connector before mating — a dirty end face is the single most common cause of an unexplained fibre fault.

Transceivers

A switch port with a fixed medium commits the chassis to one cabling decision for its lifetime. A cage that accepts a pluggable transceiver lets the same port run multimode today, single-mode next year, or direct attach copper to the adjacent rack — without replacing the switch.

Use wavelength division to send and receive on a single strand rather than a duplex pair, halving the fibre count on a constrained run. Both ends must be a matched upstream and downstream pair.

The transceiver, fibre type, and wavelength must agree at both ends. A 1310 nm single-mode optic will not usefully drive an OM3 multimode strand, and vendor firmware may refuse an unrecognised third-party module outright.

Distribution Systems

5.1  Distribution & Cable Distribution Systems

Objective 2.4 leaves the protocol stack behind entirely and asks about the building. A network that is flawless in configuration still fails if the riser is undocumented, the rack loses power at 03:00, the intake air is 40 °C, or a sprinkler head discharges over a live switch. A structured cabling design is hierarchical for the same reason a routed network is: it localises change. Traffic enters the building once, aggregates at one main frame, fans out to floor-level frames over a small number of high-capacity backbone runs, and only then radiates to individual outlets.

Demarcation point

The legal and physical boundary where the provider's responsibility ends and yours begins — in practice the NIU, smartjack or ONT in the entrance facility. Faults are triaged against it: if the provider's side tests clean, the problem is yours.

Entrance facility

Where outside plant enters the building. Houses the demarc, the provider's terminating equipment and the protection devices that stop an outdoor surge travelling inside on the copper.

MDF — Main Distribution Frame

One per building. The provider circuit terminates here and the core switching, routing and edge firewall live here, so it is usually also the server room. Every backbone run traces back to this single frame.

IDF — Intermediate Distribution Frame

A floor-level or wing-level closet fed from the MDF. Access switches, patch panels and a local UPS sit here, and horizontal cabling radiates to the work areas on that floor.

Backbone vs horizontal cabling

Backbone (riser / vertical) connects MDF to IDF and is almost always fibre — long runs, aggregated traffic. Horizontal runs IDF to outlet in copper, limited to a 90 m permanent link plus 10 m of patch cords: 100 m of channel.

Racks and mounting

The 19-inch rack is the standard width. Height is counted in rack units, where 1U = 1.75 in and a full cabinet is typically 42U. Two-post relay racks suit patch panels and switches; four-post cabinets carry the depth and weight of servers.

Patch & fibre distribution panels

Horizontal runs terminate permanently on the rear of a patch panel — 110 block for copper — and patch cords connect the front to a switch port. A fibre distribution panel does the same for fibre and includes a service loop so the cable never bends inside its minimum radius.

Lockable equipment & plenum rating

Physical access to a switch is administrative access to it, so cabinets lock front and rear. Any cable in an air-handling space needs a plenum-rated jacket — a fire-code obligation about smoke toxicity, not a performance rating.

5.3  Power Distribution Systems

Every device in the rack is downstream of a chain — utility feed, generator, UPS, PDU, rack outlet, power supply — and the chain is only as available as its least redundant link. Dual power supplies achieve nothing if both cords land on the same PDU on the same circuit.

UPS · standby

Switches to battery when the utility fails. Cheapest, with a brief transfer time the load must tolerate. Fine for a workstation, not for a distribution frame.

UPS · line-interactive

Adds an autotransformer that corrects sags and swells without touching the battery — so the battery is spent on outages, not on poor mains quality.

UPS · double-conversion

Rectifies to DC and re-inverts continuously, so the load never sees a transfer at all. The datacentre choice, at the cost of efficiency and heat.

PDU — power distribution unit

Distributes one feed to many rack outlets. Basic just splits the circuit; metered reports real draw; switched lets an outlet be power-cycled remotely — the difference between a five-minute fix and a drive to site. An ATS PDU accepts two feeds and fails over between them.

Power load & the 80 % rule

Continuous load should not exceed 80 % of a circuit's rating, so a 20 A circuit is planned to 16 A. Sizing to nameplate ratings overstates real draw badly; size to measured load with headroom for inrush.

Voltage

Equipment is commonly dual-voltage, accepting roughly 100–240 V. Running a rack at 208 or 230 V rather than 120 V carries the same power at lower current — less heat in the conductors, more equipment per circuit.

A / B feeds and generators

Dual-corded equipment takes one supply from an A-side PDU and the other from a B-side PDU, on separate circuits and ideally separate UPSs. The UPS covers seconds to minutes; a generator on an automatic transfer switch covers hours to days.

5.4  Heating, Ventilation & Air Conditioning

Cooling in a datacentre is an airflow problem before it is a refrigeration problem. Servers draw cold air at the front and exhaust hot air at the back; the entire discipline is keeping those two air masses apart. Once exhaust air recirculates into an intake, adding cooling capacity treats the symptom while the hot spot remains.

Hot aisle / cold aisle & containment

Racks are arranged in rows with all fronts facing one another across a cold aisle and all rears facing one another across a hot aisle. Cold supply air is delivered only to the cold aisle; hot exhaust collects only in the hot aisle and returns to the units. Containment takes it further by physically sealing one aisle with doors and a roof so the two air masses never mix — cold-aisle containment encloses the supply side, hot-aisle containment encloses the exhaust and ducts it back to the plenum. Containment is what makes a higher supply temperature safe, and a higher supply temperature is where the efficiency saving comes from.

Blanking panels & floor seals

An empty rack unit is a short circuit for air — exhaust flows straight back through the gap to the intake. Blanking panels close unused U space and brush grommets seal cable cut-outs in a raised floor. Both are trivially cheap and among the most effective fixes for a hot spot.

Port-side intake & exhaust

Most switches move air front to back, but some move it back to front so the port side faces the cold aisle. Mixing both airflow directions in one row puts one device's exhaust into its neighbour's intake, so the airflow variant must be specified at purchase.

Temperature & humidity

ASHRAE TC 9.9 recommends an inlet range of 18–27 °C with a dew point of −9 to 15 °C and RH not exceeding 60 %. Measure at the rack inlet, not the room thermostat. Too dry invites electrostatic discharge; too damp invites condensation and corrosion.

CRAC vs CRAH

A computer room air conditioner contains its own refrigeration compressor. A computer room air handler uses chilled water from a central plant and only moves air across a coil. CRAH scales better in large facilities; CRAC is simpler in a single room.

5.5  Fire Suppression Systems

A server room presents a conflict: the standard response to fire is water, and water destroys exactly what you are trying to protect. Purpose-built suppression resolves it by detecting earlier than a sprinkler head would, and by extinguishing with something that leaves no residue.

EPO — emergency power off

A clean agent discharge is normally interlocked with shutting down power and HVAC. Continuing to move air through the room would dilute the agent below its design concentration and let the fire re-establish.

Room integrity matters

A gaseous agent only works if the enclosure holds it. Cable penetrations, floor voids and door seals must be fire-stopped, or the agent leaks out before the fire is out.

Detection buys the time

Suppression is not the only control. Aspirating detection can alarm on a failing power supply well before there is enough heat to trigger anything else — which makes suppression optional rather than inevitable.

Standards to recognise

NFPA 75 covers fire protection for IT equipment spaces; NFPA 2001 covers clean agent systems. The exam does not test clause numbers, but it expects you to know a server room is treated differently from an office.

Taken together these four systems define whether a design survives contact with a building. Objective 2.4 is examined as judgement rather than recall: given a rack that keeps overheating, an outage that took down one of two supposedly redundant feeds, or a room protected only by a wet pipe sprinkler, the question is which physical system was specified wrongly.

6.2  Wireless Antennas & Radiation Patterns

An antenna adds no energy — it redistributes it. Gain, quoted in dBi against a theoretical isotropic radiator, is a measure of concentration, not amplification: an antenna that reaches further in one plane has necessarily given up coverage in another. Every 3 dB of gain doubles effective radiated power in the favoured direction, and costs an equivalent amount elsewhere.

Omnidirectional (dipole)

Radiates evenly through 360° in the horizontal plane. The pattern is a torus — a doughnut around the antenna axis — with a null directly above and below. That is why a ceiling omni covers the floor beneath it well and the floor above poorly, and why raising gain flattens the doughnut: more reach across the floor, less coverage immediately below.

Directional — patch / panel

Radiates into a defined lobe, typically 60–120° wide, with a flat back that suppresses radiation behind it. Wall-mounted, it pushes coverage into the room instead of into the car park — better signal and better security at once.

Yagi–Uda

A driven element with a reflector behind and several directors in front. Each parasitic element re-radiates in phase along the boom, producing a narrow forward lobe with high gain and a very small back lobe. A common choice for medium-range point-to-point links.

Parabolic dish

A reflector focuses energy onto a feed at the focal point — the narrowest beamwidth and highest gain of the common types. Aiming becomes critical: a few degrees of misalignment on a long link can cost more than the gain was worth.

MIMO

Several transmit and receive chains on one channel. Spatial multiplexing sends independent streams that arrive with different multipath signatures and are separated at the receiver. Notation is transmit × receive : streams — 4×4:4.

MU-MIMO

Serves several clients at once on the same channel by directing separate spatial streams at each. Downlink arrived with 802.11ac Wave 2; 802.11ax added the uplink direction.

Beamforming

The transmitter adjusts the relative phase of each element so wavefronts add constructively at the client and cancel elsewhere. Explicit beamforming uses channel-sounding feedback, so it works best when both ends support it.

6.3  Wireless Frequencies & Channel Overlap

The three unlicensed bands are not interchangeable. Lower frequency propagates further and penetrates building materials better; higher frequency carries more spectrum and therefore more capacity. Choosing a band is really a decision about whether the deployment is range-limited or capacity-limited.

Channel width is a trade

Doubling the width doubles the theoretical rate and halves the number of non-overlapping channels. A 40 MHz channel in 2.4 GHz consumes most of the band and is almost always wrong; 80 MHz in a dense 5 GHz deployment often causes more contention than the extra width recovers.

Co-channel vs adjacent-channel

Two APs on the same channel co-operate — they hear each other and take turns, costing throughput. Two APs on partially overlapping channels cannot decode each other and simply raise the noise floor, which is worse. Reuse deliberately rather than sliding one channel across.

Band steering & 802.11h

Band steering delays probe responses on 2.4 GHz so dual-band clients land on 5 or 6 GHz. 802.11h adds DFS and TPC so Wi-Fi can share 5 GHz with radar — near an airport, DFS channels may be effectively unusable.

Power is not coverage

Raising AP transmit power extends the downlink but not the client's weaker uplink, producing clients that can hear the AP and cannot be heard back. Cell size is set by lowering power and adding APs, not by turning one up.

802.1X, EAP and RADIUS

The three roles

The supplicant is the client, the authenticator is the AP or controller, and the authentication server is RADIUS. The authenticator relays EAP without being able to read the credentials.

EAP-TLS vs PEAP

EAP-TLS uses certificates on both sides — nothing to phish or spray. PEAP and EAP-TTLS tunnel a password inside TLS: far easier to deploy, but the security collapses if clients skip server-certificate validation.

RADIUS ports

UDP 1812 authentication, UDP 1813 accounting. Legacy implementations used 1645 / 1646, which still appear in config files.

When security fails

Rogue access point

An unauthorised AP attached to your wired network — often a staff member plugging in a consumer router. It bypasses every wireless control because the threat is already behind the firewall. Wireless intrusion detection and switch port controls are what find it.

Evil twin

An attacker-run AP broadcasting your SSID with a stronger signal, relaying client traffic through itself. Mutual authentication is the defence: with EAP-TLS or a validated server certificate the client refuses the impostor.

Deauthentication attack

Management frames were unauthenticated originally, so a forged deauth could disconnect any client and force a re-association to capture the handshake. 802.11w Protected Management Frames sign them — optional under WPA2, mandatory under WPA3.

WPS brute force & downgrade

The 8-digit WPS PIN is validated in two halves, cutting the search space to about 11,000 attempts — there is no safe configuration, disable it. An SSID advertising WPA3 and WPA2 for compatibility can also be pushed back to WPA2.

Guest networks & captive portals

How a captive portal works

The client associates and gets an address, but the network holds it in an unauthorised state. HTTP requests are intercepted and redirected to a portal page; once the visitor accepts the terms or authenticates, the controller moves that MAC into the authorised state and forwarding begins.

The walled garden

The small set of destinations reachable before authentication — DNS, the portal itself, and any identity provider it calls out to. Everything else is blocked until the session is authorised.

Segmentation is the real control

The guest SSID belongs on its own VLAN with an internet-only policy, and client isolation should be on so two guests on the same SSID cannot reach each other.

What a portal does not give you

Acceptance of terms is not encryption. Unless the guest SSID uses OWE or WPA3, traffic on it is in the clear over the air, and the portal login is only as private as the HTTPS session carrying it.

The through-line of this module is that wireless problems are rarely solved by the setting they appear to be about. Poor throughput in a crowded office is usually a channel-width and cell-size decision rather than a hardware limit; a client that connects but cannot pass traffic is usually an authentication or VLAN problem rather than a radio one; and a fully patched, correctly encrypted network can still be defeated by an access point somebody plugged in under a desk.

7.1  Ethernet Fundamentals & Network Devices

Switching is where most real networks are actually built, and where most real faults actually live. A router decides which network a packet belongs to; a switch decides which physical port a frame leaves by. Ethernet has two halves: an addressing and framing scheme that has barely changed since 1980, and a media access method that has become almost irrelevant — knowing which is which is the difference between answering an exam question correctly and repeating something that stopped being true 25 years ago.

MAC addressing

48 bits, OUI + device ID

Twelve hex digits. The first 24 bits are the OUI assigned to the manufacturer by the IEEE; the last 24 are assigned by that manufacturer. Looking up an OUI tells you who made an unknown device in your MAC table.

The I/G and U/L bits

The least significant bit of the first octet is I/G — set means multicast, which is why every multicast MAC has an odd first octet. The next bit is U/L — set means locally administered, which is how randomised phone MACs avoid colliding with real OUIs.

Broadcast — FF:FF:FF:FF:FF:FF

All 48 bits set. Every device in the broadcast domain must receive and process it. This single fact is the reason VLANs exist and the reason a switching loop is catastrophic rather than merely inefficient.

CSMA/CD — and why it no longer runs

Carrier Sense: listen before transmitting. Multiple Access: every station shares one collision domain, so one conversation at a time. Collision Detection: two simultaneous transmissions superimpose, each station sends a 32-bit jam signal, then applies binary exponential backoff — wait a random number of slot times from 0 to 2n−1, capped at 1023, abandon after 16 collisions.

But: a switch port is its own collision domain, and a full-duplex link has separate TX and RX paths — a collision is physically impossible, so CSMA/CD is disabled. If you see late collisions on a modern switch port, the cause is almost always a duplex mismatch: one end hard-coded full, the other auto-negotiating to half.

How a switch forwards

Learn → Flood → Forward → Age

Learn the source MAC against the ingress port. Flood out every port in the VLAN if the destination is unknown, broadcast or unregistered multicast. Forward out one port if known, and filter if the destination is on the ingress port. Age entries out after 300 s idle.

Store-and-forward vs cut-through

Store-and-forward buffers the whole frame and validates the FCS — higher latency, no corrupt frames propagated. Cut-through forwards after reading the destination MAC — lower latency, will forward corrupt frames. Fragment-free reads the first 64 bytes as a compromise.

Collision domain vs broadcast domain — examined constantly

A hub is one collision domain and one broadcast domain. A switch gives each port its own collision domain but remains one broadcast domain. A router — or a VLAN — is what actually creates a second broadcast domain.

7.2  VLANs & VLAN Configuration

A switch out of the box is a single flat broadcast domain. A VLAN partitions it into several independent logical switches: two ports in different VLANs cannot exchange a frame no matter how they are cabled — traffic between them must be routed, which means it can be filtered.

Access Port

Carries exactly one VLAN and sends frames untagged. The end device has no idea a VLAN exists — the switch adds membership on ingress and strips it on egress. Every port facing a PC, printer or camera is an access port.

Trunk Port

Carries multiple VLANs over one physical link by inserting an 802.1Q tag into each frame. Switch-to-switch, switch-to-router, switch-to-hypervisor. The tag is what lets one cable do the work of many.

Native VLAN — the untagged exception

One VLAN on a trunk is carried untagged, by default VLAN 1, for devices that cannot read tags. Both ends must agree which VLAN it is — a mismatch merges two broadcast domains silently.

Voice VLAN & SVI

A voice VLAN lets an access port additionally carry one tagged VLAN for an IP phone, so a phone and the PC behind it land in different VLANs on one cable. An SVI is a virtual L3 interface for a whole VLAN, given an IP so it can be that VLAN's gateway.

7.3  Spanning Tree Protocol (STP)

Redundant links between switches are essential for availability and fatal without protection. An IP packet has a TTL that decrements at every router, so a routing loop eventually kills the packet. An Ethernet frame has no TTL field at all. A broadcast that enters a loop is copied and forwarded forever, at line rate, in both directions.

Broadcast storm

One broadcast is flooded, returns on the redundant link, is flooded again, and multiplies. Within seconds links are saturated and switch CPUs are pinned — including your management session.

MAC table instability

The same source MAC keeps arriving on different ports, so the entry is rewritten thousands of times per second. Even unicast forwarding becomes unreliable.

Multiple frame copies

One unicast frame reaches the destination more than once by different paths, breaking protocols that assume Ethernet delivers at most one copy.

How STP converges — the three-step election

1
Elect one Root Bridge

Every switch starts by claiming to be root and advertising its Bridge ID in BPDUs. The Bridge ID is a 4-bit priority multiplier + 12-bit extended system ID (the VLAN) + the switch's base MAC. Priority defaults to 32768. Lowest Bridge ID wins: priority is compared first, and if priorities tie, the lowest MAC decides. Leaving priorities at default means the oldest switch in the building becomes your root by accident. Set it deliberately.

2
Every non-root switch elects one Root Port

The single port with the lowest cumulative path cost back to the root. Cost is per-link and inversely related to bandwidth — 10 Gbps = 2, 1 Gbps = 4, 100 Mbps = 19, 10 Mbps = 100. Ties break on lowest sender Bridge ID, then lowest sender port ID.

3
Every segment elects one Designated Port

On each link, the port with the lowest cost to root is designated and forwards. Every port on the root bridge is designated by definition. Any port that is neither a root port nor a designated port is blocked — that is where the loop is broken.

PVST+, Rapid PVST+ and MSTP

PVST+ runs one instance per VLAN, so different VLANs can use different roots and therefore different physical paths — excellent load distribution, expensive in CPU at scale. MSTP (802.1s) maps many VLANs onto a few instances, giving the path diversity without the per-VLAN cost.

PortFast + BPDU Guard — always together

PortFast skips listening and learning on host-facing ports so a PC gets link immediately instead of waiting 30 s for DHCP. BPDU Guard shuts that port down the instant it receives a BPDU — which is what stops somebody plugging an unmanaged switch under a desk and taking over your spanning tree. A PortFast port without BPDU Guard is an instant loop waiting to happen.

Root Guard and Loop Guard

Root Guard prevents a port from ever becoming a root port, so a downstream switch cannot claim to be root. Loop Guard blocks a port that unexpectedly stops receiving BPDUs, covering the unidirectional-link case where a port would otherwise wrongly transition to forwarding.

7.4  Network Access Control (NAC)

Spanning tree decides which ports may forward; NAC decides which devices may connect at all. Physical access to a network port has historically been the same thing as network access — NAC is what breaks that equivalence.

802.1X port-based authentication

Three roles & EAPOL

The supplicant is software on the client, the authenticator is the switch port, the authentication server is RADIUS. Before authentication succeeds the port forwards nothing except EAPOL frames — the client has link and has no network.

Dynamic VLAN assignment

RADIUS can return VLAN attributes with the accept, so the switch places the port in a VLAN chosen by identity rather than by cabling. The same wall socket puts a contractor in one VLAN and a finance laptop in another.

Guest & restricted VLANs

A device with no supplicant drops into a guest VLAN with internet only; a device that authenticates but fails posture goes to a restricted VLAN reaching only the remediation server.

MAB — MAC Authentication Bypass

Printers, cameras and badge readers have no supplicant. MAB submits the device's MAC to RADIUS as a username. It is a fallback, not a security control — a MAC is trivially spoofed.

Port security is not 802.1X

Port security authorises a MAC address; 802.1X authorises an identity. A spoofed MAC defeats the first entirely and the second not at all. Where both are available, 802.1X is the control and port security is defence in depth. And the cheapest NAC of all: administratively shut down unused ports and assign them to an unused VLAN.

7.5  Maximum Transmission Unit (MTU)

MTU is the largest payload a link will carry in one frame. It is trivial to state and a persistent source of faults that present as anything but MTU — a session that establishes and then hangs, a website that loads its HTML and stalls on an image, a VPN that passes ping and fails file transfers.

Why jumbo frames help

Each frame carries fixed per-frame overhead and costs an interrupt. Moving 9000 bytes in one frame instead of six cuts that overhead roughly sixfold — which matters for iSCSI, NFS, backup and vMotion. It does nothing useful for web browsing.

Jumbo frames are all-or-nothing

Every device in the path — both NICs, every switch, any router between — must use the same larger MTU. One switch left at 1500 does not fragment the frame; it discards it. Enable jumbo frames on an isolated storage VLAN, not across a campus.

Fragmentation, PMTUD and the black hole

  • Fragmentation and the DF bit. An IPv4 router receiving a packet larger than the outgoing MTU either fragments it or, if Don't Fragment is set, drops it and returns ICMP Type 3 Code 4 — fragmentation needed. IPv6 removed router fragmentation entirely: only the source may fragment.
  • Path MTU Discovery. The sender transmits with DF set and relies on those ICMP messages to learn the smallest MTU along the path, then sizes packets to fit.
  • The PMTUD black hole. If a firewall blocks ICMP Type 3 Code 4 — a very common over-tightening — the sender never learns to reduce packet size. Small packets pass, so the connection establishes and ping works; the first full-size packet is dropped silently and the session hangs. A TCP handshake that succeeds followed by a transfer that stalls is the signature of this fault.
  • MSS clamping. The practical workaround — the router rewrites the Maximum Segment Size in the TCP handshake so both ends agree from the outset to send segments that fit the tunnel, without depending on ICMP getting through.

The pattern worth carrying out of this module is that Layer 2 faults rarely announce themselves as Layer 2 faults. A VLAN missing from a trunk's allowed list looks like a dead application. A native VLAN mismatch looks like an intermittent security problem. A blocked spanning tree port that should be forwarding looks like a slow network. A blocked ICMP message looks like a broken server. In each case the switch is doing precisely what it was configured to do — and the diagnosis is knowing which of these five mechanisms is making the decision.

APIPA is a diagnosis, not a configuration

A host finding no DHCP server self-assigns from 169.254.x.x and verifies uniqueness with ARP. It reaches other APIPA hosts on the same segment and nothing else — there is no gateway and no DNS. Seeing 169.254 means the DHCP server is unreachable, the scope is exhausted, or the VLAN is wrong.

The two addresses you can never assign

In every subnet the all-zeros host portion is the network ID and the all-ones host portion is the broadcast. That is why usable hosts are 2ⁿ − 2 — and why a /31 is a special case: RFC 3021 allows it on point-to-point links because neither reserved address is needed there.

8.2  IPv4 Data Flows

How many destinations a single packet is aimed at determines how the network handles it, and IPv4 has exactly three answers.

Unicast — one

Destination is the host's own address. Routed anywhere. Almost all traffic: HTTP, SSH, SMB, DNS queries.

Broadcast — all

255.255.255.255 (limited) or the subnet broadcast such as 192.168.1.255 (directed). Stops at the router. ARP, DHCP Discover, legacy NetBIOS.

Multicast — a group

224.0.0.0/4 — 224.0.0.0 to 239.255.255.255. Routable with IGMP. IPTV, stock feeds, OSPF hellos at 224.0.0.5.

Broadcast cost is why VLANs exist

Every host must interrupt its CPU to process every broadcast, even to discard it. A flat /16 with thousands of hosts spends measurable CPU on ARP alone — the practical argument for VLANs, not just the security one.

Directed broadcast is disabled for a reason

255.255.255.255 is never forwarded by any router. A directed broadcast such as 192.168.1.255 targets a remote subnet and could in principle be forwarded — which was the basis of the Smurf amplification attack, so it is off by default everywhere.

Multicast needs IGMP snooping

Hosts join groups with IGMP; switches use snooping to avoid flooding multicast to ports with no subscriber. Without snooping a switch treats multicast like broadcast and the efficiency gain disappears.

IPv6 has no broadcast at all

Removed deliberately and replaced with well-scoped multicast — ff02::1 all-nodes, ff02::2 all-routers. Anything that was broadcast in IPv4 is a specific multicast group in IPv6.

8.3  Assigning IPv4 Addresses

Every host needs four things to work beyond its own subnet: an address, a mask, a default gateway and a DNS server. How those four arrive is the choice between static and dynamic assignment.

DHCP — the DORA exchange

D — Discover

Client broadcasts to 255.255.255.255 from source 0.0.0.0, because it has no address yet. UDP 68 → 67.

O — Offer

Each server offers an address plus mask, gateway, DNS and lease. The client takes the first offer — exactly how a rogue DHCP server hijacks a network.

R — Request

Client broadcasts acceptance, naming the server it chose so the others release their reservations.

A — Acknowledge

Server confirms and commits. Renewal at 50 % of lease (T1), rebinding at 87.5 % (T2).

DHCP relay / IP helper

Discover is a broadcast, and routers do not forward broadcasts — so a DHCP server on another subnet is unreachable by default. The router is configured as a relay agent (ip helper-address) to convert that broadcast into a unicast toward the server. A whole VLAN on APIPA while another works is usually a missing helper address.

Reservation versus static

A reservation lives on the DHCP server and ties an address to a MAC — the client still runs DHCP and still receives updated options. A static address is on the client and receives nothing. Reservations are better for printers and appliances precisely because gateway and DNS changes still propagate.

When static is right

Routers, switch management interfaces, firewalls, and the DNS and DHCP servers themselves. Anything that must be reachable before or during a DHCP failure cannot depend on DHCP.

Reading the APIPA symptom

One host on APIPA → that host's link or NIC. One whole VLAN on APIPA → the relay, the scope, or the trunk. Everything on APIPA → the DHCP server itself.

Subnetting is done in binary whether you write the binary down or not. There are exactly three facts to memorise — the powers of two, the octet bit values, and the fact that the mask's boundary is where the 1s stop. Everything else is derived.

The four formulas

subnets = 2s

Where s is the number of bits borrowed from the host portion. Borrowing 2 bits from a /24 gives 2² = 4 subnets.

usable hosts = 2h − 2

Where h is the number of remaining host bits. The −2 removes the network ID and the broadcast. This is the formula you invert when a question gives you a host requirement.

magic number = 256 − mask octet

For /26 the interesting octet is 192, so 256 − 192 = 64. Subnets then start at every multiple of 64: .0 .64 .128 .192. This single trick removes almost all of the arithmetic from a subnetting question.

broadcast = next network − 1

Once you have the block size you never calculate a broadcast directly. A subnet starting at .64 with block 32 ends immediately before .96 — so its broadcast is .95 and its usable range is .65–.94.

Why VLSM was worth the effort

Addresses actually consumed

64 + 32 + 4 = 100 of the 256 available, leaving 192.168.1.100 – 192.168.1.255 — 156 addresses — free for future subnets.

What fixed-length subnetting would cost

Using /26 uniformly consumes 3 × 64 = 192 addresses and leaves only one /26 spare. The router link alone would get 62 usable addresses to satisfy a requirement of 2 — wasting 60. VLSM saves 92 addresses on a single /24.

Why the order matters

Allocating the /30 first would place it at .0–.3, and the next /26 boundary is .64 — so the /26 could not start until .64 and everything between .4 and .63 would be stranded. Largest first keeps every block aligned to its own boundary.

How to check your work

Each network ID must be an exact multiple of its own block size. .0 is a multiple of 64, .64 is a multiple of 32, .96 is a multiple of 4. If a network ID is not a multiple of its block size, the subnet is misaligned and the arithmetic is wrong.

8.6  IPv6 Addressing & Data Flows

The address is 128 bits, written as eight groups of four hexadecimal digits separated by colons. That is 2128 addresses — enough that exhaustion stops being a design consideration, which changes how the protocol works rather than merely how big the numbers are.

IPv6 compression — two rules, applied in order 
Full address:
  2001:0db8:0000:0000:0000:ff00:0042:8329

Rule 1 - drop LEADING zeros in each group (never trailing):
  2001:db8:0:0:0:ff00:42:8329

Rule 2 - replace ONE run of consecutive all-zero groups with ::
  2001:db8::ff00:42:8329

:: may appear only once. If it appeared twice the address would be
ambiguous - you could not tell how many zero groups belong to each.

  2001:db8::1:0:0:1     valid   (:: covers groups 3-4)
  2001:db8::1::1        INVALID (which run does each :: cover?)

How an IPv6 host gets its address

Link-local first, always

Every interface derives an fe80:: address as soon as IPv6 is enabled, before any router is heard from. Neighbour Discovery and Router Solicitation both run over it.

SLAAC — stateless autoconfiguration

The host sends a Router Solicitation; the router replies with a Router Advertisement carrying the /64 prefix. The host generates its own interface identifier and combines the two. No server holds any state — that is the meaning of stateless.

EUI-64 and privacy extensions

EUI-64 builds the interface identifier from a 48-bit MAC: split it in half, insert fffe in the middle, invert the seventh bit of the first octet. Privacy extensions now generate a random identifier instead — precisely because EUI-64 exposes the MAC address.

DHCPv6 and DAD

Stateful DHCPv6 assigns the address; stateless DHCPv6 lets SLAAC assign it and supplies only DNS and other options. Duplicate Address Detection is mandatory: before using any address the host sends a Neighbour Solicitation to its own tentative address.

A dual-stack client attempts IPv6 and IPv4 nearly simultaneously and uses whichever completes first, so a broken IPv6 path degrades performance instead of breaking the application. Without it, a misconfigured IPv6 route produces long timeouts that look like a server fault.

Every tunnel is an MTU problem

Encapsulation reduces the payload available to the inner protocol. Tunnelled IPv6 that pings successfully then stalls on a large transfer is the same PMTUD black hole from Module 7, arriving by a different route.

Firewall both stacks

An IPv4 rule set does not filter IPv6. A host carefully firewalled on IPv4 and reachable over an auto-configured IPv6 address is a genuinely common oversight — and SLAAC means the IPv6 address may exist without anyone having configured it.

The /64 convention

SLAAC requires a 64-bit interface identifier, so IPv6 subnets are /64 essentially without exception — even a point-to-point link, where the IPv4 instinct would be to use the smallest possible block. Conserving IPv6 addresses is not a goal.

9.1  Routing Fundamentals & Routing Tables

A switch answers “which port on this network?”. A router answers “which network?” — and then hands the packet to somebody else who asks the same question again. No router in the internet knows the full path to any destination; each knows only the next step, and the path emerges from a chain of independent local decisions.

The analogy. A routing table is a set of road signs at a junction. The sign does not show the whole route — it says “Jakarta, that way”. You drive to the next junction and read the next sign. The router never knows whether the journey succeeds; it only guarantees the next step is correct according to what it has been told.

Next hop and exit interface

The next hop must be an address the router can already reach on a directly connected network. On a point-to-point link the exit interface alone suffices; on Ethernet the next hop is also required, because the router must ARP for a specific neighbour.

Default route — 0.0.0.0/0

A prefix length of zero means no bits have to match, so it matches anything. Because longest prefix match always prefers a more specific entry, the default is used only when nothing else fits. It is why a branch router with 40 routes still reaches the whole internet.

Recursive lookup

A static route saying via 203.0.113.1 forces the router to first look up how to reach 203.0.113.1. A route whose next hop cannot itself be resolved is never installed — the usual explanation for a static route that appears in the config but not in the table.

RIB is not FIB

The RIB is the control plane's collection of everything learned. From it the router derives a FIB — a hardware-optimised structure the forwarding path consults per packet. Remember this separation: it is exactly what SDN takes apart and relocates.

9.2  Route Selection

There are two separate decisions here, and conflating them is the single most common misunderstanding on this topic. One picks which routes get installed in the table at all; the other picks which installed route a given packet uses. They run at different times, use different criteria, and never override one another.

Stage 1 — control plane

Which routes get installed

Two different sources offering the same prefix → lower administrative distance wins, the other is discarded. The same source offering several paths → lower metric wins. AD first, metric only within one protocol.

Stage 2 — forwarding

Which installed route a packet uses

Every packet is matched against all installed routes and the longest prefix match wins. AD plays no part here — a /24 learned by RIP (AD 120) still beats a /16 learned by OSPF (AD 110) for an address inside that /24.

Metrics — what each protocol actually measures

RIP — hop count

Just the number of routers crossed. A three-hop path over gigabit loses to a two-hop path over a 1 Mbps line — the fundamental defect of the protocol. Max 15; 16 means unreachable.

OSPF — cost

cost = reference bandwidth ÷ interface bandwidth, default reference 100 Mbps. That default makes every link at or above 100 Mbps cost 1 — so gigabit and fast-ethernet look identical. Raising the reference identically on every router is standard practice.

EIGRP — composite metric

By default a function of the lowest bandwidth along the path plus cumulative delay, computed by DUAL — which keeps a pre-validated backup, the feasible successor, so failover needs no recomputation.

BGP — attributes, not a metric

BGP does not measure speed at all. It walks an ordered list — weight, local preference, locally originated, shortest AS_PATH, origin, lowest MED — and stops at the first that decides. This is policy, not performance, which is why the fastest path across the internet is frequently not the one taken.

Floating static routes and ECMP

A static route with a deliberately high AD — say 250 — sits idle while the dynamic route exists and is installed only if the protocol withdraws it: the standard way to configure a backup link that must not carry traffic while the primary is healthy. When several paths tie on both AD and metric, the router installs all of them and load-shares (ECMP) — normally per-flow, so a single TCP session does not arrive out of order.

9.3  Routing Protocols

The first division is by scope. An Interior Gateway Protocol runs inside a single autonomous system — one organisation, one administrative policy — and its job is to find the technically best path. An Exterior Gateway Protocol runs between autonomous systems, and its job is to enforce business policy about whose traffic you will carry. There is exactly one EGP in use on the internet, and it is BGP.

Distance Vector — RIP

Bellman-Ford

Mechanism. Each router tells its directly connected neighbours the full contents of its own routing table plus its distance to each destination. Hearing “I can reach 10.1.0.0/16 at cost 3”, a router installs it at cost 4 via that neighbour. This is often called routing by rumour: no router ever sees the topology, only what neighbours claim.

Analogy. Asking the person next to you how far the station is, and adding one step. If everyone answers honestly it works. If somebody repeats back what you told them, you both start counting upwards forever.

Count-to-infinity, and the fixes. Split horizon stops a router advertising a route back out of the interface it learned it on. Route poisoning advertises a failed route at cost 16 — infinity — rather than staying silent. Holddown timers refuse better news about a route that just failed until the network settles. Limits: max 15 hops, full-table updates every 30 s whether anything changed or not. RIPv2 added masks (classless) and moved to multicast 224.0.0.9.

Link State — OSPF

Dijkstra SPF

Mechanism. Every router describes only its own directly attached links in a Link State Advertisement and floods that description unchanged to every other router in the area. Each router therefore assembles an identical Link State Database — a complete map — and independently runs Dijkstra's shortest path first algorithm over it with itself as the root.

Analogy. Instead of asking neighbours for directions, everyone contributes their own street to a shared map, and each person plans their own route from the finished map. Nobody has to trust anyone else's arithmetic — which is why link state converges fast and cannot suffer count-to-infinity.

Why areas exist. Dijkstra's cost grows with database size, and every topology change forces every router in the area to re-run it. Areas partition the database: a change inside Area 1 is recomputed only by Area 1's routers and summarised to everyone else. Area 0 is the backbone, and every other area must connect to it — inter-area traffic always transits Area 0.

Roles & timers. An internal router has all interfaces in one area; an ABR sits on the edge of two and summarises between them; an ASBR redistributes routes in from outside OSPF. Hellos go to 224.0.0.5 every 10 s, dead after 40 s. On a multi-access segment a DR/BDR is elected so n routers form n adjacencies instead of n(n−1)/2. A neighbour stuck in EXSTART almost always means an MTU mismatch — straight back to Module 7.

Path Vector — BGP

AS_PATH

Mechanism. BGP advertises a prefix together with the complete list of autonomous systems the advertisement has traversed — the AS_PATH. A router seeing its own AS number already in the path discards the advertisement. That is how loops are prevented, with no metric and no timer at all.

Analogy. A parcel with the full delivery chain stamped on the outside. If you see your own stamp on it, it has come back to you and you refuse it.

eBGP vs iBGP. eBGP runs between different autonomous systems, usually a single hop across a peering link. iBGP runs inside one AS to carry external routes across it — and by design an iBGP router does not re-advertise iBGP-learned routes to other iBGP peers, which is why full-mesh, route reflectors or confederations are required. Transport is TCP 179, so it inherits reliable ordered delivery; it sends the full table once at session establishment and only incremental updates afterwards — essential at roughly a million prefixes.

9.4  Configuring Routers

Cisco IOS syntax, which is what the exam uses. The pattern generalises: address the interfaces, tell the router what it does not learn by itself, then verify against the routing table rather than against the configuration.

Static routing and a default route 
! Address the interfaces first - nothing routes without connected networks
interface GigabitEthernet0/0
  description LAN
  ip address 10.1.1.1 255.255.255.0
  no shutdown
!
interface GigabitEthernet0/1
  description WAN to ISP
  ip address 203.0.113.2 255.255.255.252
  no shutdown
!
! Static route: destination, mask, next hop
ip route 10.2.0.0 255.255.0.0 10.1.1.2
!
! Default route - the gateway of last resort
ip route 0.0.0.0 0.0.0.0 203.0.113.1
!
! Floating static backup - AD 250 keeps it out of the table
! until the primary route disappears
ip route 10.2.0.0 255.255.0.0 192.0.2.1 250
!
! Verify
show ip route
show ip route 10.2.0.0
OSPF — single area and multi-area 
! Single area
router ospf 1
  router-id 1.1.1.1
  network 10.1.1.0 0.0.0.255 area 0
  network 203.0.113.0 0.0.0.3 area 0
  passive-interface GigabitEthernet0/0
!
! The mask in a network statement is a WILDCARD, not a subnet mask.
! It is the inverse:  255.255.255.0  ->  0.0.0.255
!
! Raise the reference bandwidth so gigabit and faster links
! do not all end up with a cost of 1. Set it identically
! on EVERY router or the costs will not be comparable.
router ospf 1
  auto-cost reference-bandwidth 100000

router ospf 1
  router-id 2.2.2.2
  network 10.1.1.0 0.0.0.255 area 1
  network 10.0.0.0 0.0.0.3   area 0

show ip ospf neighbor        ! adjacency up?
show ip ospf interface brief ! right area, right cost?
show ip route ospf           ! did the routes install?

9.5  Address Translation & Redundancy

Two problems solved at the same boundary: NAT lets many private hosts share few public addresses, and a first hop redundancy protocol stops the default gateway itself from being a single point of failure.

The four NAT address terms

Inside local

The private address as the inside host knows itself — 192.168.1.10.

Inside global

The public address that same host appears as from outside — 203.0.113.5.

Outside global

The public address of the external host being contacted, as it really is.

Outside local

That external host as it appears to inside hosts. Usually identical to outside global.

How PAT distinguishes sessions. The translation table keys on the full tuple — inside address, inside port, outside address, outside port — and rewrites the source port to a unique value per session. That is why one public address supports tens of thousands of concurrent connections, and why a single host opening too many sessions can exhaust the table.

An address not owned by any single physical interface. In an FHRP it is the gateway configured on every client; in a load balancer it is the front-end address. Either way, the address survives the failure of the device currently answering for it.

One physical interface divided into several logical ones, each with its own VLAN tag and IP. This is router-on-a-stick — the same mechanism from Module 7 — and it is how a router provides inter-VLAN routing over a single trunk.

Why FHRP matters operationally

A statically addressed host points at one gateway forever. Without an FHRP, replacing that router means touching every host. With one, the virtual IP stays constant and the physical router behind it can be swapped during business hours.

9.6  Multicast Routing & GRE Tunnels

Two mechanisms that exist because ordinary unicast routing cannot express what is needed: one delivers a single stream to many receivers without duplicating it, the other carries traffic a router would otherwise refuse to forward.

The problem multicast solves

Sending one video stream to 500 receivers by unicast means transmitting it 500 times. Multicast transmits once and lets the network replicate the packet only where the paths to different receivers diverge.

IGMP — who wants it

Hosts use IGMP to tell their local router which groups to join. v2 added explicit leave messages; v3 added source-specific filtering. Switches use IGMP snooping to avoid flooding the group to ports with no member.

PIM — how it gets there

Protocol Independent Multicast builds the distribution tree using whatever unicast routing table already exists. Dense mode floods first and prunes back; sparse mode is explicit-join through a Rendezvous Point and suits the far more common case where most segments do not want the traffic.

The RPF check

Reverse Path Forwarding is the loop-prevention rule: a multicast packet is accepted only if it arrived on the interface the router would itself use to send unicast traffic back to the source. Arriving anywhere else, it is silently dropped.

Reserved local-scope groups worth memorising

224.0.0.1 all hosts · 224.0.0.2 all routers · 224.0.0.5 all OSPF routers · 224.0.0.6 OSPF DRs · 224.0.0.9 RIPv2 · 224.0.0.10 EIGRP. Everything in 224.0.0.0/24 is link-local and is never forwarded off the segment.

GRE tunnels

What it does

Generic Routing Encapsulation wraps an arbitrary payload in a new IP header, so two routers separated by an intervening network appear directly connected. IP protocol 47, roughly 24 bytes of overhead.

Why GRE is paired with IPsec

IPsec tunnel mode carries unicast IP only, so it cannot transport OSPF hellos or EIGRP updates — which are multicast. Wrapping them in GRE first turns them into unicast that IPsec will accept. That is why the phrase in production is almost always GRE over IPsec, never GRE alone.

GRE provides no security

No encryption, no authentication, no integrity checking. Anything requiring confidentiality must be paired with IPsec. Treating a GRE tunnel as private because it is called a tunnel is a genuine and recurring mistake.

Always an MTU question — and recursive routing

24 bytes of overhead leaves an effective MTU of about 1476. Tunnels that ping successfully then stall on a large transfer are the PMTUD black hole from Module 7; MSS clamping on the tunnel interface is the usual fix. And if the route to the tunnel's own destination is learned through the tunnel, it tries to carry itself and flaps continuously.

9.7  Beyond the Traditional Model — SDN

Academic note — architectural evolution

Everything described in this module shares one architectural assumption: every router carries both a control plane, which decides where traffic should go, and a forwarding plane, which moves it there. The intelligence is distributed, and the network's behaviour is emergent — no single component holds the whole picture, and convergence is what happens when hundreds of independent devices happen to agree. Software Defined Networking inverts that. The control plane is lifted out of the individual devices and centralised in a controller with a genuine global view of the topology, while the devices are reduced to programmable forwarding elements. The controller pushes flow entries down over a southbound interface such as OpenFlow or OVSDB, and a software switch — Open vSwitch being the canonical implementation, and the forwarding plane underneath most OpenStack and container networks — simply executes match-and-action rules it did not compute. Northbound, applications and orchestration systems ask the controller for outcomes rather than configuring devices individually. The gain is that policy becomes a property of the network rather than of each box: a change is expressed once instead of being configured consistently on forty routers and hoped for. The costs are real — the controller becomes a critical dependency, the control channel becomes a latency and failure domain of its own, and a network that cannot reach its controller must fall back on cached state. In practice the two models have converged rather than one replacing the other: SD-WAN applies centralised policy over ordinary internet transport, and EVPN-VXLAN fabrics use a BGP control plane to distribute reachability into a programmable overlay — centralised intent, distributed protocols still doing the forwarding underneath.

The thread running through this module is that routing is a chain of independent local decisions, and almost every routing fault is a disagreement between two of them. A route in the configuration but not the table is a recursive lookup that failed. Traffic on the wrong path is longest prefix match doing exactly what it should against a summary somebody added. An OSPF neighbour that will not form is a parameter mismatch, not a cabling fault. Diagnosis is a matter of asking, at each hop in turn, what that particular router believed and why — which is also precisely the visibility that centralising the control plane was designed to provide.
